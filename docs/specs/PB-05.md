## 1. Purpose

Where a visitor opts into the weekly Love in Action digest.

**Scope deviation from the live page:** the live form offers four separate mailing lists on one page. Three of them, the monthly newsletter, educational events, and donor events, belong to the Alliance's other Wix-managed lists and have no table or logic anywhere in this system. Build only the digest checkbox. Reproducing checkboxes that don't connect to anything would silently promise subscriptions that never happen. The other three lists (monthly newsletter, educational events, donor events) are intentionally absent, not forgotten. They come back once each has a real webhook or sync path into this system; until then, offering them would silently do nothing. See `LIA_Phase_Two_Backlog.md` item 9.

**The list is in scope this week. The send is not.** The Thursday demo does not send to the live subscriber list; real cutover is the following week (D46).

## 2. Entry and exit

**Arrives from:** PB-00 digest button, site navigation, and links on browse pages.

**Leaves to:** confirmation on the same page after successful submit by default.

`/unsubscribe/:token` remains a separate public route on this surface's unsubscribe path, reached only from an emailed link. Build for clarity; the current Wix list uses its own unsubscribe mechanism.

## 3. Data

**Reads:** `digest_subscribers` by `lower(email)` on subscribe, and by `unsubscribe_token` on unsubscribe.

**Writes:** `digest_subscribers`. Inserts a new row on first subscribe, or updates `status` on resubscribe or unsubscribe.

**Functions called:** None.

**Never touches:** `people`. `digest_subscribers.person_id` is left null on signup (D27).

## 6. Actions

**Submit**
- Enabled when: digest checkbox is checked and all required fields validate.
- Does: inserts a `digest_subscribers` row at `status = 'subscribed'`, or updates an existing row per section 12.
- Transaction boundary: single write.
- Emails queued: none (D28).
- On success: confirmation per section 8.
- On failure: failure message, entered values retained.

**Unsubscribe, on link visit**
- Does: sets `status = 'unsubscribed'` and `unsubscribed_at` for the row matching the token.
- Renders confirmation. No further action required.

## 7. Conditional behavior

| Trigger | Result |
|---|---|
| Digest checkbox unchecked | Submit blocked |
| Email already subscribed | Success message per section 12 |
| Email previously unsubscribed | Resubscribed, success message |

## 11. Authorization

None. Both subscribe and unsubscribe routes are public.

The unsubscribe token is the authorization on `/unsubscribe/:token`.

Subscribe is rate limited by IP with a per-endpoint ceiling (D10).

## 12. Error paths

| Failure | Rendered result |
|---|---|
| Email is already subscribed | Normal success message. Never disclose list membership |
| Email exists at `unsubscribed` | Set back to `subscribed`, normal success message |
| Email exists at `bounced` | Set to `subscribed` (D29) |
| Token not found or already used | Plain message, not a 404 |
| Write fails | Failure message, values retained |
