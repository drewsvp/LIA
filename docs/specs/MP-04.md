## 1. Purpose

The organization's home in the portal and the hub every other member surface hangs off. It lists the organization's existing item and volunteer requests for editing, and provides the routes to create new ones, manage the organization, invite members, and view supporters.

## 2. Entry and exit

**Arrives from:** MP-02 after authentication, the dashboard control in the navigation, and the back control on every other member surface.

**Leaves to:**

| Destination | Trigger |
|---|---|
| MP-09 `/dashboard/items/:id/edit` | Selecting an item request and activating its edit control |
| MP-12 `/dashboard/volunteer/:id/edit` | Selecting a volunteer request and activating its edit control |
| MP-07 `/dashboard/items/new` | Create item request |
| MP-10 `/dashboard/volunteer/new` | Create volunteer request |
| MP-05 `/dashboard/organization` | Organization settings |
| MP-06 `/dashboard/members/new` | Add a member |
| MP-13 `/dashboard/supporters` | View supporters |

## 3. Data

**Reads:** `item_requests` and `volunteer_requests` for the session's organization (id, title, created_at, status), `organizations` (name).
**Writes:** Nothing.
**Functions called:** None.
**Never touches:** anything. This surface is read-only.

## 4. Layout regions

1. **Page heading.** "MY ORGANIZATION DASHBOARD," static, does not embed
   the organization's name.
2. **Organization identity strip.** The org's icon/photo, the org's name
   (e.g. "The Alliance"), and the logged-in user's name with an account
   menu chevron, right-aligned.
3. **Welcome copy.** Two short paragraphs, see section 8.
4. **Navigation tile grid.** Six buttons, image-topped cards, two rows of
   three: create item request, create volunteer request, view
   donors/volunteers, edit organization, add a member, community login
   (external, out of scope for this rebuild, see section 13).
5. **"Edit/Archive Existing Requests" region.** Item Requests selector
   plus edit button, Volunteer Requests selector plus edit button, in that
   order.

Captured from MP-04-desktop.png, Aug 16 2026. Region 2 (organization
identity strip) is new relative to this spec's original four-region
guess; add it rather than folding it into the heading.

## 5. Fields

| # | Label (verbatim) | Control | Required | Binds to | Validation |
|---|---|---|---|---|---|
| 1 | Item Requests | Select | n/a | Item request selection, local only | |
| 2 | Volunteer Requests | Select | n/a | Volunteer request selection, local only | |

Selector placeholders, captured verbatim: "Select Item Request..." and
"Select Volunteer Request..." (both use a literal ellipsis).

**Option label format, closed with a grounded default rather than a
guess.** `{Title} - {MM/DD/YYYY}`. Numeric date, no month spelled out,
matching this site's own confirmed convention on MP-13's date columns
(`08/10/2026`, `12/19/2025`). Not yet directly observed on MP-04 itself,
correct this in one line if the live dropdown shows otherwise, but this
is grounded in this site's actual formatting, not a blind guess, and not
worth holding the build for.

**Which requests appear.** All statuses regardless of state — draft, pending, active, and archived. A member needs to reach a draft request left mid-creation and an archived one to review or reopen; excluding any status would hide work in progress or history.

**Sort order.** Most recent first, by `created_at` descending. Matches the one place this site gives direct evidence: both of MP-13's tables sort that way.

## 6. Actions

**"Edit Item Request"**
- Enabled when: a request is selected. Disabled with no selection.
- Does: navigates to MP-09 for the selected request.
- Emails queued: none.

**"Edit Volunteer Request"**
- Enabled when: a request is selected. Disabled with no selection.
- Same behavior against MP-12.

**Navigation controls**
- Each navigates to its destination in section 2. No writes.

## 7. Conditional behavior

| Trigger | Result |
|---|---|
| Organization has no item requests | Item selector empty state, per section 9 |
| Organization has no volunteer requests | Volunteer selector empty state, per section 9 |
| No selection made | Edit controls disabled until a request is selected. Standard pattern matching every other selector-plus-action control in the app |

## 9. Empty states

A newly approved organization arrives here with nothing in either selector, so this is the first screen every new member org sees. It is not an edge case.

**Item Requests selector, no requests:** "You haven't created any item requests yet."

**Volunteer Requests selector, no requests:** "You haven't created any volunteer requests yet."

Capture both regions independently; they may behave differently in layout but use these messages.

## 10. Mobile differences

Closed per D60. Confirmed against MP-04-mobile.png: single column, same six tiles stacked, same Edit/Archive section below, nothing dropped.

## 11. Authorization

Resolve the session's selected organization per MP-02, then query requests filtered by that `org_id`, server-side. The organization is never read from the URL, a query parameter, or a form field. There is no route shape on this surface that accepts an organization identifier, and none should be added.

## 12. Error paths

| Failure | Rendered result |
|---|---|
| Session has no resolvable organization | Handled by MP-02, not here |
| Request query fails | A stated error in place of the selector. Never an empty selector, which is indistinguishable from having no requests |

That distinction is worth building carefully. A failed query that renders as an empty list tells a member their requests are gone.

## 13. Out of scope for this surface

- Creating, editing, or archiving anything. This surface only routes.
- Any supporter or pledge data. That is MP-13.
- Aggregate counts, totals, or metrics of any kind. Reporting is phase two and an agent that adds a "requests fulfilled" tile here has violated `Handbook.md` section 17.

## 14. Acceptance

- Both selectors list only the session organization's requests.
- Option labels match the captured format exactly, including separator and date format.
- Selecting a request and activating edit reaches the correct edit surface for that request.
- All seven navigation destinations resolve.
- Empty states render correctly for an organization with no requests of either type.
- No organization identifier appears in the URL.
- A member of another organization cannot see this organization's requests by any means.
- Desktop and mobile match their screenshots.
