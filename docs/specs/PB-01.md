## 1. Purpose

The public list of item needs. A visitor scans active requests, searches to narrow them, and opens one to donate. This is the top of the donation funnel and most of its traffic arrives from social links on phones, so the mobile layout carries more weight here than anywhere else in the system.

## 2. Entry and exit

**Arrives from:** the site navigation, social and email links, PB-00, the legacy hub redirect, and PB-02 via back navigation.
**Leaves to:** PB-02 `/items/:id`, by selecting a request card.

An unmatched legacy request identifier also lands here rather than on a 404, per `Handbook.md` section 11.

## 3. Data

**Reads:** `item_requests` where `status = 'active'`, joined to `organizations` where `kind = 'member_org'` and `status = 'approved'`. Fields: request title, description, image, organization icon/logo, and the organization's name and city.

**Writes:** Nothing.
**Functions called:** None.

**Never returns:** any contact person, any email or phone, any supporter data, any request not `active`, or any organization not `approved`. The public filter is a shared query helper, written once and used by PB-01 through PB-04. It is not re-implemented per surface.

## 4. Layout regions

1. **Page heading and introductory copy.** Search intro copy, then bold search-instruction line, then search input.
2. **Search region.**
3. **Request list.** A card per active request, full list at once. No pagination visible across roughly thirty rendered cards, matching PB-03's finding: the full list renders at once, not paginated.

Confirmed against PB-01-desktop.png, Aug 16 2026.

### Card contents

Confirmed order: org icon, photo, title, "Requesting Organization" plus org name, "City" plus value, "Description" plus truncated text, button "Learn More / View Details."

**Use "City," not "Location."** That label belongs to PB-03 only. Item requests don't have their own location, only the org's city.

**Location value is the organization's `city`.** It resolves through the request's `org_id` and there is no other source. This is why `city` is required on every approved organization; see `Handbook.md` section 14.

Card styling tokens are in `Design.md`: 5px radius and the confirmed box shadow.

## 6. Actions

**Learn More / View Details** (per card)
- Enabled when: always.
- Does: navigates to PB-02 for that request.
- No write.

**Search input**
- Filters the list as the visitor types, debounced.
- Searches: request title, organization name, and organization city.
- **Debounce interval: 300ms**, closed per C7 (Aug 16 2026), applied identically on PB-01 and PB-03.
- Case-insensitive substring matching across all three fields unless capture proves otherwise.
- No write, no navigation, no page reload.

## 7. Conditional behavior

| Trigger | Result |
|---|---|
| Visitor types in search | List filters after the debounce interval |
| Search matches nothing | Empty state per section 9 |
| Search cleared | Full list returns |
| A request has no image | Standard placeholder graphic, same as PB-03's closure |

## 9. Empty states

Two, independent per region:

- **No active requests at all.** "No items needed right now, check back soon or browse volunteer opportunities instead." Link to PB-03.
- **Search matched nothing.** "No items match your search."

## 10. Mobile differences

Closed per D60. Single column, same card contents in the same order, full-width cards and search input.

## 11. Authorization

None. Public by design.

The authorization work on this surface is negative: confirming that nothing beyond the fields in section 3 is serialized into the response. Check the response body, not the rendered page.

## 12. Error paths

| Failure | Rendered result |
|---|---|
| Request query fails | A stated error. Never an empty list, which reads as no needs currently posted |
| A request's organization does not resolve | Exclude that request from the list and log it |

## 13. Out of scope for this surface

- Any claim or donation action. That happens on PB-02.
- Filtering by population, city, or organization beyond search. Search only.
- Sorting controls.
- Pagination, load-more, or infinite scroll.
- Counts, totals, or impact figures of any kind.

## 14. Acceptance

- Only `active` requests belonging to `approved` `member_org` organizations appear.
- Each card shows org icon, photo, title, organization name, city (labeled "City"), truncated description, and the Learn More / View Details control.
- Search filters on all three fields and is case-insensitive.
- Search debounce is 300ms.
- Full list renders at once with no pagination control.
- Both empty states render with their captured text when observed.
- The response payload contains no contact details, no email, no phone, and no supporter data.
- A failed query renders a stated error, not an empty list.
- Card shadow and radius match the `Design.md` tokens.
- Desktop and mobile match their screenshots.
